# The `--rt-ctx` reserved context register (x28 AArch64 / r14 x86_64) is a WHOLE-PROGRAM con

> The rt ctx reserved context register x28 AArch64 / r14 x86 64 is a WHOLE PROGRAM contract, but the scratch audit only…

The `--rt-ctx` reserved context register (x28 AArch64 / r14 x86_64) is a WHOLE-PROGRAM contract, but the scratch audit only scanned the generated runtime (`generate_runtime_with_features`). User codegen was never checked and borrowed r14 freely: `runtime_callable_invoker` used it as its type-tag register and then called the PHP callable through it, so every closure-driven usort/array_filter/array_reduce/array_walk/array_any ran its callback with a tag where the context pointer belongs — five SIGSEGVs on linux-x86_64. `static_properties` used it for class-id comparisons too. Two consequences: (1) any audit of a register contract must cover BOTH the runtime text and the emitted user assembly, and (2) localizing such a crash needs one binary per helper, because a buffered stdout loses whatever it still held when the process dies — the last PASS line printed is NOT the last check that ran.
Evidence: 29 micro-probes x 2 modes in a linux/amd64 container: 5 CRASH (exit 139), all --rt-ctx only, all callback-invoking array helpers; legacy versions of the same 5 pass. `test_cli_rt_ctx_user_codegen_never_scratches_the_ctx_register` reports 23 offenders on the emitted x86_64 assembly, 16 removed by moving the invoker tag to rbx and the class-id compare to r15.</evidence>
